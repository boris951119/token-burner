`from <模块名> import <函数>`（模块名即文件名，可同进程导入互不冲突）。
单文件目标 ≤400 行：本模块的页面与逻辑要能在几百行里写完，写完一条需求就
收一条。若你发现自己在写一个上千行的文件，那是模块拆得过粗的信号——把
跨模块可复用的部分放进 _shared/（见下方标记块），其余属于别的模块的职责
不要代劳。超长文件在后续修复通道里按整文件重发，越长越修不动（实测

若职责里有「本模块 ATOMIC」清单：只实现清单内条目，禁止把整站页面/导航/

公共依赖（多模块共用的工具函数 / 类型 / 常量）统一放 _shared/，禁止各模块

注意：<文件名.py> 必须是纯文件名（如 utils.py），不含任何路径——系统会自动存入 code/_shared/ 目录。

【文案硬契约（评测逐字断言）】需求原文中带引号的字符串——UI 文案、
种子数据、标签/分类名——是硬性契约：必须**逐字**出现在对应界面、表单
占位符或种子数据中，保持原文语言、大小写与拼写，**禁止翻译、禁止
改写、禁止意译**。UI 文案语言跟随需求原文语言（需求是英文则界面
用英文）；需求未给引号文案时，界面语言仍与需求原文一致。
本段刻意不给任何文案示例：示例串会被当成内容写进代码（实测有交付把
提示词示例做成了别的题目的页面标题与种子行），需求原文是唯一来源。

【页面渲染硬规则（本模块一旦输出 HTML/页面就适用，与模块名无关）】
- 渲染层必须从库里读：列表页/首页上的每一条条目都由存储查询结果生成，
  首屏条目数等于库里该视图的条目数。手写若干条静态样例（不接库）是实测里
  最贵的一种死法：库中条目的名字在页面上根本不存在，按名/按角色定位从第一
  条用例起就落空，且任何写操作之后页面内容不变，整族交互用例连带判红；
- 元素由语义标签承载（评测按可访问性角色+名字定位，非语义实现等于不存在）：
  按钮=<button>、链接=<a href>、单行输入=<input>（同时给 label 与 placeholder）、
  多行=<textarea>、勾选=<input type=checkbox>、下拉=<select>、条目=<article>
  （条目级操作按钮写在该 article 内部）、表格=<table><tr><td>、弹窗=<dialog>
  （带可访问名）；
- 需求点名的点击对象必须「点下去有变化」：要么在 <form> 内提交，要么由页内
  脚本真实改变可见状态；卡内/行内操作按钮常驻 DOM 比悬停才渲染更稳；
- 同一页面同一角色下不得出现同名（含大小写变体）的重复控件；只在编辑态或
  内部状态才出现的修饰词不得进导航/侧栏这类公共定位面；按需求新建条目时，
  新名字与既有种子条目同名会并排两张同名卡（按名定位命中多个即判歧义），
  需求未明确允许同名并存时按替换/去重处理；
- 种子初始化每次进程启动都会重复执行，必须幂等：不得追加重复条目，调整条目
  归类时旧关联先清掉，由关联表聚合出的标签/分类列表渲染前去重；需求没声明
  的关联不得自行加挂。

【首页硬契约（`/` 这一条路由承载全站得分面）】
- `/` 必须是需求所描述那个应用的**业务主页面**：题面点名的种子条目、
  导航项与可见控件直接渲染在这页上（需求先描述哪个视图，首页就是那个
  视图本身；把它交给第一个业务页的 302 跳转也算达标，页面内容不用复制）；
- 以下形态都不含题面点名的条目与控件，把它们放上 `/` 等于交了个空应用
  （首页之后的每一条用例都拿不到可点的东西）：①项目自述页（列出本项目
  有哪些模块/页面/接口/函数/功能的清单，或"访问 /xxx 查看…"的导览）
  ②只有一句欢迎语的空壳页 ③默认响应不是业务页面、要按 Accept 头或参数
  才切内容的混合页。这类自述内容确有必要时放 /about 之类的次要路由，
  首页只放业务内容；
- 首页与其余页面同一条规则：正文由存储查询结果生成，逐字承载需求原文
  点名的条目与文案（见上两段），不得在首页上另写一套演示数据。

【页面族与存储硬规则（实测覆盖面第一大户，逐模块适用）】
- 需求点名的每个页面/视图都是一条独立交付物，不是同页文案：题面里出现
  「进入 X」「在 X 页」「X 详情」「X 列表」这类说法时，X 必须①有自己的
  GET 路由（返回含该页正文的完整 HTML；把内容并进别的页面就地展开不算，
  只回 JSON 让浏览器停在一段文字上也不算），②有从首页就能点到的真实控件
  （点下去 URL 或可见状态确实换成 X 的内容；评测只从首页进入，
  深链永不被访问，首页没有入口的页面在评测眼里等于不存在）；
- 首页/总览上的聚合与摘要区（跨实体的"最近""最常""统计"这类块）必须真实
  存在，内容由跨表聚合查询得出，不得整块省略、不得写死样例；需求描述了
  这类区却只交出单实体列表页，是实测里成簇判红的一种；
- 一个应用只有一张真库：所有模块（含种子、认证、标签、设置这类辅助模块）
  读写同一份存储、同一批表，禁止每个模块各开一个数据库文件或各建一份同名
  表——聚合页要跨实体读数，分了库就对着一张空表渲染，页面照样出得来但
  内容永远为空；同一个库的路径解析表达式在全项目必须唯一（同一个文件名
  多处各自拼接，进程内会解析成两个不同文件，写入与读取落在两处）。


【蓝图惯例硬规则（机械装配只认顶层 `_bp`）】
- 凡本模块含 HTTP 路由：必须在**模块顶层**写
  `_bp = Blueprint("<本模块名>", __name__)`，全部端点用 `@_bp.route(...)`
  （或 `@_bp.get/post/...`）注册；
- **禁止**把路由藏在函数内 `Flask()` / 局部 `Blueprint` / 未导出的别名上——
  装配层扫描不到 → API 全 404（实测 20 模块只挂上 3 个的死法）；
- 入口工厂模块（含 `create_app` + `register_blueprint`）除外：它负责把各
  模块的 `_bp` 挂进应用，自身可以不导出 `_bp`。
