# Demo 录制分镜脚本(3-5 分钟)

> 目标:向评委展示「一句需求 → 可运行项目」的完整闭环,突出
> 生产轨迹可审计与实测数据。录制前准备见文末清单。

## 分镜 1:开场(20 秒)

- 画面:PPT 封面页(token-burner · v1.0.0)
- 口播:"这是 token-burner——输入一句软件需求,交付一个可运行、
  经真实测试验收的项目。这是刚发布的 v1.0.0。"

## 分镜 2:输入需求(40 秒)

- 画面:Web 工作台(http://127.0.0.1:8000),需求输入框
- 操作:输入示例需求(如"开发一个待办事项 CLI:增删改查+JSON 持久化+优先级")
- 口播:"唯一的人工输入就是这一句话。点「点火」。"

## 分镜 3:全自动流水线(60-90 秒,可 2-4 倍速)

- 画面:工作台实时进度(评估 → 组队 → 方案讨论 → spec → 模块循环)
- 口播:"PM 模型细化方案,两个评审模型打分收敛;spec 确认后自动拆分模块;
  每个模块经历写码、测试、九道门禁与真实 pytest 执行,
  未通过自动进入修复循环——全程无需人工。"
- 重点停在:**模块卡片**(SUCCESS/修复次数)与 **token 曲线**(成本实时可见)

## 分镜 4:交付与验收(40 秒)

- 画面:交付汇总 + 切到文件管理器展示项目目录
- 操作:依次打开 `spec.md` → `logs/cost_report.json`(逐调用成本)
  → `changelog/*/validation.md`(验收报告)→ 运行 `python -m xxx.cli`
- 口播:"交付物不只是代码——规格、接口契约、逐调用成本审计、
  每模块验收报告全部留痕。生成的 CLI 现在就能跑。"

## 分镜 5:实测数据收尾(40 秒)

- 画面:基准报告(SWE-bench 风格柱状图:47%→57%→71%)
- 口播:"在 10 类真实需求的标准化基准上,模块通过率 71%,
  任务交付 10/10,零预算超支。1035 项自动化测试护栏,
  v1.0.0 已在 GitHub 发布。"

## 录制前清单

- [ ] `python -m app.server` 已启动,浏览器打开工作台
- [ ] 连接已配好(右下角面板,探针绿灯)
- [ ] 示例需求文案已复制到剪贴板
- [ ] 录屏软件(Windows: Win+G / OBS),分辨率 ≥1080p
- [ ] (可选)预先跑通一遍,确认当次模型速度可接受
- [ ] PPT 与本脚本分屏备查

## 备注

- 全程目标 3-5 分钟;超时优先压缩分镜 3(倍速)
- 若模型响应慢:分镜 3 用已有交付物(examples/logscan)讲生产轨迹,
  现场生成留到"附录"或直播环节
